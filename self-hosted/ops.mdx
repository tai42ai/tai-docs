Operational caveats a self-hosted deployment runs into. Each links to the deeper
platform page where it applies.

## Reverse proxy in front

`serve` speaks plain HTTP on its published port and puts nothing in front of it —
terminate TLS at your own reverse proxy or load balancer and forward to that
port. The Studio and the `/api` surface share one origin, so there is nothing to
split.

<Warning>
Recreating a container gives it a **new IP**. A name-based reverse proxy that
resolves the upstream once at startup keeps forwarding to the old address after
an upgrade or restart and starts failing. Re-resolve on each request, or reload
the proxy when the stack is recreated. On the Compose network use the service
name (`serve`), not a captured IP.
</Warning>

<Warning>
Some record identifiers carry an **encoded slash** (`%2F`) in the URL path. A
proxy or gateway that normalizes paths — or that decodes, rewrites, or redirects
encoded slashes — corrupts those paths, and the requests fail. Configure the
proxy in front of `serve` to pass `%2F` through unchanged: do not normalize,
decode, or redirect an encoded slash in the request path.
</Warning>

Some features need the public origin spelled out rather than inferred:
[connectors](/concepts/connectors) accept an OAuth redirect only when its origin
is in `CONNECTORS_REDIRECT_URI_ALLOWLIST`. See [TLS and the front
door](/operate#tls-and-the-front-door).

## Restarts and bundle settings

The bundle's app services run with `restart: unless-stopped`. Keep that policy: a
change to a [recycle-class setting](/concepts/config-and-secrets#settings-profiles)
makes the affected processes exit gracefully, and Compose starts them again. Without a
restart policy, an exited process stays down.

Every key the compose file sets to a non-empty value for an app service, and every
`ENV` the image sets, belongs to the deployment (a key left empty, such as an unset
`${SANDBOX_DOCKER_HOST:-}`, does not). A key one service's own `environment:` sets
belongs to the deployment for every service on the same worker bus: its value wins over a
value stored in `config/.env`, Studio shows it locked, a save that sets it is refused, and
no such service applies a stored copy of it; a service the compose file does not give
the value runs its `TAI_DEFAULT_*` fallback or the field's default. Change it in the compose file (or
the `.env` it reads) and recreate the containers. A setting an admin should edit from
Studio stays out of the compose file. See
[Deployment values and stored values](/concepts/config-and-secrets#deployment-values-and-stored-values).

## Backups

The application state lives in Postgres and Redis, and in the two persistent
mounts (the config directory and the plugin prefix). Back up all of them.

- **Datastores** — snapshot the Postgres and Redis volumes on your own schedule;
  the image holds no state.
- **Stored platform state** — the runtime exports its own state (access-control
  policies, presets, and whatever else plugins register) as a backup document
  with `tai backup export`. See [Back up and restore](/operate/backup-and-restore).
- **Config** — keep `config/manifest.yml` and the plugin prefix, so a restored
  server boots with the same manifest and the same runtime-installed plugins.

## Schema migrations

`tai db migrate` applies every pending file across all components; `tai db status`
reports each component's applied/pending/checksum verdict without changing
anything, and exits non-zero when any is out of date — so it doubles as a
pre-deploy gate:

```bash
tai db status
```

Both commands connect through each component's bound [named
database](/concepts/config-and-secrets#named-databases) and its **admin**
identity — `TAI_DATABASE_<NAME>_PG_ADMIN_*`, the DDL-privileged role, falling back
to that database's runtime role when unset — distinct from the app's runtime store
role. The chain model, the [`tai_schema_history`](/concepts/marketplace#the-migrations-contract)
source of truth, the forward-only rule, and the checksum-immutability constraint
are the [migrations contract](/concepts/marketplace#the-migrations-contract).
Because recovery is a restore-and-re-migrate, never a rollback, snapshot the
database before any schema-carrying upgrade — see [Back up and
restore](/operate/backup-and-restore#recovering-from-a-bad-migration).

## Health probes

The server exposes unauthenticated `/health` (liveness) and `/ready` (every wired
store, pinged under a 5s budget) routes for orchestrators and load balancers —
served public by the app's own route-level declaration, so no allowlisting. The
bundle's serve healthcheck already probes `/health`. `/ready` additionally fails
(and the process exits, so its supervisor starts it again) when one of the server's
long-lived background tasks stops unexpectedly, naming the stopped task in its
response. The full probe semantics are
[Liveness and readiness](/operate/deploy#liveness-and-readiness).

The `backend` container serves no `/health`. Its worker reports each pass of its
loop into a liveness file, and `tai42-backend-probe`, which ships in the image,
run in that container exits `0` while the file is fresh and `1` once the loop has
stopped passing. [Backend processes](/operate/deploy#backend-processes) gives
each backend process's probe, its settings, and its timing.

## Observability

`tai metrics` serves the Prometheus multiprocess endpoint on its own port and
reads the metrics directory the app process writes, so it runs beside that
process on the same filesystem — its own service on serve's volume in the
Compose bundle, a sidecar container in the same pod on Kubernetes. Query traces
and aggregate metrics with `tai obs`. See [Observe](/operate/observe).
