Install the runtime from PyPI. `tai42-skeleton` pulls `tai42-contract` and
`tai42-kit` with it, so one install puts the whole runtime and the `tai` command
on your path.

## Requirements

- **Python 3.13 or newer.**
- **Redis 7.0+ and Postgres** only for the features that need them — access
  control, connectors, and interactions. Local tools and mounted MCP servers
  need no services at all.

## Install the runtime

```bash
pip install tai42-skeleton
```

[`uv`](https://docs.astral.sh/uv/) works the same way and is what every
repository in the ecosystem uses:

```bash
uv add tai42-skeleton
```

## Add the standard toolbox

The `toolbox` extra pulls in the `tai42-toolbox` contrib package — its generic
tools and its composition extensions (`chain`, `batch`) load straight from a
manifest:

```bash
pip install 'tai42-skeleton[toolbox]'
```

See the [standard toolbox guide](/guides/standard-toolbox) for what ships in it.

## Add an identity provider before turning on access control

Access control is off by default, and the runtime refuses to boot with
`ACCESS_CONTROL_ENABLE=true` and no identity provider registered. Install the
Redis-backed API-key provider and name it in the manifest — that is the pairing
every access-controlled install starts from:

```bash
pip install tai42-identity-redis
```

```yaml manifest.yml
lifecycle_modules:
  - tai42_identity_redis.redis_api_key_provider
```

The provider stores key hashes in Redis, so an access-controlled server needs a
reachable Redis instance. [Access control](/concepts/access-control) explains the
policy model, and the [access-control guide](/guides/access-control) mints the
first key.

## Work from the source checkouts

Contributors run against side-by-side clones instead. `tai42-skeleton`'s
`[tool.uv.sources]` points at `../tai-contract` and `../tai-kit`, so the three
repositories must sit next to each other:

```bash
git clone https://github.com/tai42ai/tai-contract
git clone https://github.com/tai42ai/tai-kit
git clone https://github.com/tai42ai/tai-skeleton
cd tai-skeleton
uv sync --extra dev
```

## The `tai` command

Installing the package puts the entrypoint on your path under two names, `tai`
and `tai42`. Both run the same command tree — `tai` is the documented one, and
`tai42` is an alias for environments where an unrelated `tai` already sits on
your PATH. Three subcommands run the long-lived processes:

- `tai serve` — run the MCP server.
- `tai backend` — run the agent / worker backend process.
- `tai metrics` — serve the Prometheus metrics endpoint.

Run `tai --help` for the full command tree, or browse the
[CLI reference](/reference/cli/index).
