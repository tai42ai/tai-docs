## EXPRESSION_EDITOR_CONTRACT_VERSION

```ts
const EXPRESSION_EDITOR_CONTRACT_VERSION: 1
```

The contract version an `ExpressionEditorContribution` must target. Bumped
only on a BREAKING change to `ExpressionEditorProps` or the contribution
shape; the registry rejects a contribution whose `contractVersion` is not
exactly this, so a host never mounts an editor built against an incompatible
props contract. It is distinct from `STUDIO_PLUGIN_API_VERSION`: the plugin API
gains this whole extension point ADDITIVELY (that version does not move), and
this narrower number then versions the editor props independently.


## ExpressionControlProps

```ts
type ExpressionControlProps = Omit<TextareaHTMLAttributes<HTMLTextAreaElement> & InputHTMLAttributes<HTMLInputElement>, "value" | "onChange" | "disabled" | "rows" | "placeholder" | "className" | "spellCheck" | "children">
```

The native attributes `ExpressionField` FORWARDS to its underlying control
(`Textarea` or, single-line, `TextInput`), minus the ones the field owns itself.
Intersecting both attribute sets keeps the pass-through valid whichever element
`multiline` selects, and omitting the owned keys keeps a caller from
accidentally severing the value/edit wiring or the monospace class. This is the
`inputs.tsx` pass-through doctrine (a caller's native attribute reaches the
element) narrowed to what a field can safely surrender — `name`, `onBlur`,
`maxLength`, `style`, `data-*`, and the like.


## ExpressionEditorContribution

```ts
interface ExpressionEditorContribution
```

A plugin's contribution of the editor for one expression language. The editor
rides a SEPARATE chunk (a visual canvas, converters, a language runtime), so it
is fetched lazily: `load` resolves the module exposing the `Editor` component,
and the optional `preload` warms that chunk on open-intent (hover/focus) so the
editor is ready by the time the user opens it. `contractVersion` must equal
`EXPRESSION_EDITOR_CONTRACT_VERSION` or the registry rejects it loudly.

**Properties**

| Property | Type | Description |
|---|---|---|
| `contractVersion` | `number` | The ExpressionEditorProps contract this editor was built against. |
| `language` | `ExpressionLanguage` | The language this editor authors; the lookup key a field resolves by. |
| `load` | `() => Promise<{ Editor: ComponentType<ExpressionEditorProps> }>` | Resolve the editor component's chunk; rejection surfaces as the field's loud error. |
| `preload?` | `() => void` | Best-effort warm of the editor's chunk on open-intent; never awaited by the field. |

**Related:** [ExpressionEditorProps](/reference/studio-sdk/utilities#expressioneditorprops), [ExpressionLanguage](/reference/studio-sdk/utilities#expressionlanguage)


## ExpressionEditorLauncher

```ts
function ExpressionEditorLauncher(
  props: ExpressionEditorLauncherProps,
): ReactElement<unknown, string | JSXElementConstructor<any>> | null
```

The launcher + lazily-loaded editor for one expression field, standalone so a
compact grid can drop it beside its own input. It resolves the contributed
editor for `declaration.language` itself and renders NOTHING when none is
registered (or no `ExpressionEditorsProvider` is mounted) — the same
graceful absence `ExpressionField` degrades to a plain text field on.

**Props**

| Prop | Type | Description |
|---|---|---|
| `compact?` | `boolean` | Icon-only launcher for narrow rows; the full name rides `aria-label`. |
| `declaration` | `ExpressionFieldDeclaration` | What language the field authors, what its input is, and how to sample/validate it. |
| `editorReadOnly?` | `boolean` | Open the editor READ-ONLY (no Save). This is the launcher's ONLY blocking knob: a launcher has no inline textarea to disable, so — unlike ExpressionField's `disabled`, which conflates textarea-disabled with editor-read-only — the door expresses author-blocking solely here. ExpressionField maps its own `disabled` onto this by default, and its `editorReadOnly` overrides that. |
| `fieldLabel` | `string` | The label the editor titles itself with; also enriches the launcher's name. |
| `onSave` | `(expression: string) => void` | Called with the authored expression when the user saves in the editor. |
| `title?` | `string` | Override the launcher's hover `title` (e.g. a rerun/side-effect hint). Absent, the title is derived from the declaration's shape ("Visual editor · input: …"). |
| `value` | `string` | The field's current expression ('' when unset), the editor seeds itself with. |

**Related:** [ExpressionEditorLauncherProps](/reference/studio-sdk/utilities#expressioneditorlauncherprops)

## ExpressionLanguage

```ts
type ExpressionLanguage = "jq" | string & object
```

The expression language an expression field authors. `'jq'` is the only language
that exists today; the tag is an OPEN string union so a host (or a later plugin)
can name another pipeline language without a change to this type. The literal
keeps `'jq'` on the autocomplete list while `string` keeps the union open.

## ExpressionShapeDescriptor

```ts
interface ExpressionShapeDescriptor
```

A descriptor of what the expression's input document IS for a field — the shape
the expression receives as its root. Deliberately open: a host builds these from
its own domain, so ANY envelope is expressible, including ones the editor has
never heard of. The `id` is an opaque, host-namespaced string used only for
memoisation/telemetry. Graduated from jq-studio's `JqInputShapeDescriptor` with
every field isomorphic, so the flows adapter maps its `JQType` onto this without
reshaping.

**Properties**

| Property | Type | Description |
|---|---|---|
| `blurb` | `string` | One sentence: what the input document is in this field. |
| `caveats?` | `readonly string[]` | Per-field caveats (e.g. ".iterate.item is always null in a while condition"). |
| `id` | `string` | Stable, host-namespaced id (opaque to the editor). |
| `keys` | `readonly ExpressionInputKey[]` | The top-level keys of the input document, each with a one-liner. |
| `label` | `string` | Short chip label — what the input is here, e.g. "node envelope". |
| `returns` | `string` | What the expression must RETURN, e.g. "true or false" \| "an object". |
| `sample?` | `unknown` | A static skeleton of the input document — the cheap, honest default a Test  panel seeds its input with. A host may override it dynamically through the  declaration's ExpressionSampleInputProvider. |

**Related:** [ExpressionInputKey](/reference/studio-sdk/utilities#expressioninputkey)

## hiddenToolNames

```ts
function hiddenToolNames(
  tagEntries: readonly ({ badges: string[]; hidden: boolean; name: string; tags: string[] })[],
  overlayRows: readonly ({ badges: string[]; display_name: string | null; folder_id: string | null; hidden: boolean | null; tags: string[]; tool_name: string })[],

```

The set of tool names whose EFFECTIVE visibility is hidden, from the native
declarations (`listToolTags`) merged with the tool_meta overlay (`listToolMeta`).

plugin-hidden tool correctly keeps it OUT of the set (unhidden).

## lintSchemaText

```ts
function lintSchemaText(text: string, requireTitle: boolean): SchemaLintResult
```

Parse and structurally lint a JSON-Schema editor buffer.

 - Empty text is VALID (an unset, optional schema) with a `null` schema.
 - Malformed JSON is INVALID; the parser message is surfaced verbatim.
 - A top-level value that is not a JSON object (an array or a scalar) is INVALID.
 - When `requireTitle`, a top-level string `"title"` is REQUIRED (the
   `response_format` contract the backend enforces); its absence is INVALID.

The parsed object is returned untouched — no key is normalized, reordered, or
dropped — so a schema carrying `$defs`/`anyOf` round-trips exactly.

|---|---|---|---|
| `text` | `string` | — | — |
| `requireTitle` | `boolean` | — | — |

## toolBadgesByName

```ts
function toolBadgesByName(
  tagEntries: readonly ({ badges: string[]; hidden: boolean; name: string; tags: string[] })[],
```

The raw-name → merged-badges map a tool picker reads to render the SELECTED tool's

## useExpressionEditor

```ts
function useExpressionEditor(
  language: ExpressionLanguage,
): ExpressionEditorContribution | null
```

Resolve the contributed editor for one expression language, or `null` when none
is registered OR no `ExpressionEditorsProvider` is mounted above the caller.
This is the ONLY way a plugin surface reaches a contributed editor: it cannot
enumerate or mutate the registry, only ask for one language. `null` is the
graceful-absence signal `ExpressionField` renders a plain text field on.
