The schema-driven form renderer and the JSON Schema helpers it is built on.

## CompletionProvider

```ts
type CompletionProvider = (argName: string, partial: string) => Promise<string[]>
```

Fetch argument-value suggestions for a string field. `argName` is the field's
path within the form (a property key at the root, a dotted path when nested);
`partial` is the value typed so far. The caller owns the source (e.g. an MCP
`completion/complete` call) — SchemaForm only routes string fields through the
completion-backed input when a provider is supplied.

## ExpressionFieldComponent

```ts
type ExpressionFieldComponent = ComponentType<ExpressionFieldProps>
```

The expression-authoring door a host INJECTS into the form — `JqField`, which the
host imports straight from `@tai42/jq-studio`.

It is a COMPONENT, rendered as an element, never called as a function: the door
owns hooks and state (editor open, worker handle), which only survive as its own
element identity. A host may inject a `lazy` door to keep the jq subgraph in a
split chunk — the form mounts it inside a Suspense boundary that paints the
resting shell while that chunk resolves.

**Related:** [ExpressionFieldProps](/reference/studio-sdk/schema-forms#expressionfieldprops)


## ExpressionFieldContext

```ts
const ExpressionFieldContext: Context<ExpressionFieldComponent | undefined>
```

The ambient door for the whole form. Absent (the default), an
expression-annotated field renders the PLAIN string input, byte-identically to
an unannotated one — the jq authoring door is opt-in, because the dynamic import
that would fetch it on demand still EMITS its chunks, worker, and wasm into
every consumer that bundles the SDK.

A host wires it ONCE above its tree (`SchemaEditor`'s preview and
`ElicitationForm` render forms a caller does not own the props of, and a plugin
page renders its own); the form's own `expressionField` prop overrides it for a
single form.

**Related:** [ExpressionFieldComponent](/reference/studio-sdk/schema-forms#expressionfieldcomponent)

## ExpressionInputShape

```ts
interface ExpressionInputShape
```

What `.` IS for an expression-annotated field, as the form hands it to the
injected door. Built by the renderer from the schema's `x-tai42-expression`
annotation.

Like the annotation type it is built from, this MIRRORS jq-studio's input-shape
descriptor without importing it: the schema-form tree names no jq type, in code
OR in its declarations, which is what keeps a consumer that never injects a door
free of the jq subgraph. `JqField` satisfies it structurally; a test pins that.

**Properties**

| Property | Type | Description |
|---|---|---|
| `blurb` | `string` | One sentence: what `.` is in this field. |
| `caveats?` | `readonly string[]` | Per-field caveats. |
| `id` | `string` | Stable, host-namespaced id, opaque to the door (memoisation/telemetry). |
| `keys` | `readonly ExpressionInputKey[]` | The top-level keys of `.`, each with a one-liner. |
| `label` | `string` | Short chip label — what `.` is here, e.g. "node envelope". |
| `returns` | `string` | What the expression must RETURN, e.g. "true or false". |
| `sample?` | `unknown` | A static skeleton of `.` for the door's test surface. |
| `variables?` | `readonly ExpressionInputVariable[]` | The named variables the expression reads as `$name` beside `.`; omitted when  the field declares none. |

## FieldWords

```ts
interface FieldWords
```

A form field's own words, keyed by the root object's property name in a form's
`fieldWording`. Every member is optional; an unset one draws the SDK's own word.

- `choiceLabel`: the placeholder of the field's `enum` select (in place of `Select…`).
- `invalid`: the sentence that replaces every shape error on the field and anything
  inside it (a format, pattern, length, bound, type or item error).
- `required`: the sentence shown when the field's required value is missing, at the
  field or anywhere inside it (in place of `"<name>" is required`).
- `addItem` / `removeItem` / `itemLabel` / `noItems`: a list field's add button, each
  item's remove button, each item's heading (its `{n}` token takes the item's number),
  and the line shown while the list is empty.

**Properties**

|---|---|---|
| `addItem?` | `string` | — |
| `choiceLabel?` | `string` | — |
| `invalid?` | `string` | — |
| `itemLabel?` | `string` | — |
| `noItems?` | `string` | — |
| `removeItem?` | `string` | — |
| `required?` | `string` | — |


## FormControl

```ts
type FormControl = "chips" | "textarea"
```

The CONTROL a surface draws for a property in place of the default for the
property's shape. `chips` draws a choice (a `string` with an `enum`, or an
`array` of such strings) as a tap-to-select chip grid instead of the
radio/select or checkbox group. `textarea` draws a `string` as a multi-line
text control instead of a single-line box. It changes what is DRAWN, never what
is accepted — the value and its validation stay the property's own.


## FormInputMode

```ts
type FormInputMode = "text" | "numeric" | "decimal" | "tel" | "email" | "url"
```

The input KIND a `string` field collects, drawn as the matching keyboard or
native control. The vocabulary is the HTML `inputmode`/control naming of the
concept: `numeric`/`decimal` set a text box's keyboard hint; `tel`/`email`/`url`
select the matching native control. It draws, it does not validate.

```ts
function SchemaForm(props: SchemaFormProps): ReactNode
```

Render a controlled form for `schema`. The root is usually an object (a tool's

**Props**

| Prop | Type | Description |
|---|---|---|

## SecretRef

```ts
type SecretRef = { key: string; source: "key" } | { secret: string; source: "paste" }
```

The value `SecretRefField` emits and reads back. The `source` discriminant
is what the host branches on:
 - `key`   — reference an existing env key; the host resolves the reference.
 - `paste` — a new plaintext secret; the host stores it under a generated key
             and records the reference. `secret` is write-only and never rendered.

## dateRangePairs

```ts
function dateRangePairs(
  properties: readonly readonly [string, JsonSchema][],
): readonly DateRangePair[]
```

The date-range pairs among `properties` that are drawable as ONE control. A pair
qualifies when: the END names an existing sibling START in `rangeStart`; BOTH are
`format: date`; both carry the SAME `visibleWhen` (deep-equal, or both absent); AND
no OTHER field's `visibleWhen` names either end — otherwise merging the pair would
leave that field's predicate pointing at a control that no longer draws on its own,
so the pair stays two date fields (the documented degrade). `properties` is ONE
page's ordered list; a field is used in at most one pair. Each pair also names each
end's `timeOf` time among the same properties, which draws inside the group.

**Parameters**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `properties` | `readonly readonly [string, JsonSchema][]` | — | — |

## fieldDrawingOrder

```ts
function fieldDrawingOrder(
  names: readonly string[],
  properties: Readonly<Record<string, JsonSchema>>,
): string[]
```

`names` in drawing order: each `timeOf` time moved to sit right after the date it
names. `names` is one page's fields, or every property of a page-less form or a
readback, in their given order. A time moves only when the name it points at is in
`names` and does not itself point at another listed name; any other time (its date
not listed, a chain of times, a cycle) keeps its place. Every name appears exactly
once and every other name keeps its relative order. Pure and idempotent, so every
walker that orders the same list draws it the same way.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `names` | `readonly string[]` | — | — |
| `properties` | `Readonly<Record<string, JsonSchema>>` | — | — |

## resolveRef

```ts
function resolveRef(schema: JsonSchema, root: JsonSchema): JsonSchema
```

Resolve an internal `$ref` against the document root, following chained refs
(a `$ref` whose target is itself a `$ref`). Only same-document pointers are
supported (`#/$defs/Name`, `#/definitions/Name`, `#`); an external or
unresolvable ref throws LOUDLY rather than yielding a silent empty schema.
A schema with no `$ref` is returned unchanged. A pointer cycle throws.

## validateAgainstSchema

```ts
function validateAgainstSchema(
  schema: JsonSchema,
  value: unknown,
  options?: ValidateOptions,
): SchemaFormErrors
```

Validate `value` against `schema`, returning a per-path error bag (empty =
valid). The caller runs this before submit and feeds the result back to
`SchemaForm` for display. `options.maxUploadBytes` mirrors the renderer's
`maxUploadBytes` prop so a media field's byte cap is enforced identically here;
`options.fieldWording` puts a field's own `invalid` sentence in place of the
SDK's word for any shape error on that field, and its own `required` sentence in
place of the SDK's message for a missing required value at or inside that field.
