The three dispatching branch tools every backend offers, built once over its seams.

`register_task_branches` registers the three BACKEND tool extensions. Each factory receives
``(func, name, description)`` and returns a new-named branch tool bound alongside the original:

- ``<tool>_sync_task`` queues the call and waits for its result;
- ``<tool>_async_task`` queues the call and replies with the job's id;
- ``<tool>_schedule_task`` writes a recurring schedule firing the tool.

A branch's signature is the tool's own parameters widened with the branch's options (built with
makefun, so a tool caller sees real parameters). A backend supplies only its seams: the
`TaskDoor` its task branches queue through, and the
`ScheduleWriter` its schedule branch writes through.

The options a dispatching branch tool takes beyond the tool's own arguments, and their split.

`BACKEND_TASK_OPTS` are the task options every backend honours; a backend adds its own
through `task_opts`. `SCHEDULE_OPTS` are the
schedule branch's own arguments. Each becomes a keyword argument of the branch tool, so a
dispatch's kwargs carry them beside the tool's arguments until `split_task_options` takes
them out.

Worker queue labels and the queue name each derives.

A label (letters, digits, ``_``, ``-``) names a worker pool. Its queue is
``<settings queue>.<label>``: a label holds no ``.`` or ``:``, so a derived name never equals
the settings queue, nor any key a backend builds by suffixing the settings queue with ``:``.
A worker CLI takes the label through `queue_label_option`.

What every schedule write door shares: the cadence check and the stored job kwargs.

Each door that writes a schedule (the schedule branch tool, update, import) checks the cadence
against the backend's `ScheduleWriter` before it
writes; the writer stores the record's tool inside the job kwargs it fires with.
