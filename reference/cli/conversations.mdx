Manage conversation routes.

```console
$ tai conversations [OPTIONS] COMMAND [ARGS]...
```

## `tai conversations config-delete`

Delete a per-target conversation config by (target_kind, target_name).

Example: `tai conversations config-delete agent concierge`

```console
$ tai conversations config-delete [OPTIONS] {target_kind} {target_name}
```

| Argument | Description |
| --- | --- |
| `target_kind` | Target kind: 'agent' or 'tool'. _(required)_ |
| `target_name` | The agent or tool name. _(required)_ |

| Option | Description |
| --- | --- |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |

## `tai conversations config-set`

Create or replace a per-target conversation config.

An UPSERT — a config for that (target_kind, target_name) is REPLACED if it exists
(`created` is `false` for a replace). The target must EXIST. `--greeting-template`
may reference at most the `&#123;pairing_code&#125;` placeholder; omit it (or pass an empty
value is refused) for no greeting.

Example: `tai conversations config-set agent concierge --multichannel \
--greeting-template 'Hi! Pair another channel with &#123;pairing_code&#125;'`

```console
$ tai conversations config-set [OPTIONS] {target_kind} {target_name}
```

| Argument | Description |
| --- | --- |
| `target_kind` | Target kind: 'agent' or 'tool' (must exist). _(required)_ |
| `target_name` | The agent or tool name (must exist). _(required)_ |

| Option | Description |
| --- | --- |
| `--multichannel` / `--no-multichannel` | Opt the target into person linking. _(default: `False`)_ |
| `--greeting-template` `&lt;str&gt;` | First-contact greeting; may reference the &#123;pairing_code&#125; placeholder. Omit for no greeting. |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |

## `tai conversations create`

Create or replace a conversation route.

An UPSERT — a name that already exists is REPLACED, rebinding its `execution_key`
along with everything else (`created` is `false` for a replace). A `door=api`
route's `callback_secret` is minted server-side and shown ONCE in the result; it
signs the delivery callback and is never re-readable. There is no check that you can
run the target — the execution key's live grants bound the turn. A `tool` target may
map the message to the tool kwargs (`--payload-expr`) and the result to the reply
(`--reply-expr`); a tool reply of null/blank sends nothing.

Example: `tai conversations create support-line --door channel --target-name triage \
--execution-key svc --channel twilio --identity +15550001111`

```console
$ tai conversations create [OPTIONS] {route_name}
```

| Argument | Description |
| --- | --- |
| `route_name` | Route name — a slug [a-z0-9-]+ (the thread-key handle). _(required)_ |

| Option | Description |
| --- | --- |
| `--door` `&lt;str&gt;` | Inbound door: 'api' or 'channel'. _(required)_ |
| `--target-name` `&lt;str&gt;` | The agent or tool the turn runs (must exist). _(required)_ |
| `--execution-key` `&lt;str&gt;` | The api-key user id the turn runs AS; you must own it (or be admin), tokenless-evaluable. _(required)_ |
| `--target-kind` `&lt;str&gt;` | What the turn runs: 'agent' or 'tool'. _(default: `agent`)_ |
| `--payload-expr` `&lt;str&gt;` | target-kind=tool: jq mapping the inbound message to the tool kwargs. |
| `--reply-expr` `&lt;str&gt;` | target-kind=tool: jq mapping the tool result to the reply. |
| `--channel` `&lt;str&gt;` | door=channel: the channel registry name (e.g. twilio). |
| `--identity` `&lt;str&gt;` | door=channel: the medium address we are texted at. |
| `--callback-url` `&lt;str&gt;` | door=api: the https answer-delivery URL. |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |

## `tai conversations transcript`

Read one thread's transcript (caller-scoped: your own threads, or any as admin;
channel threads are admin-only, and any thread you cannot read reads as a plain 'not
found').

`--order asc` (the default) reads oldest first; `--order desc` reads newest first,
so page 1 always holds the latest messages — the order a live tail wants. The window
pages that order from its own end.

The thread id rides the query string, so an api-door id — which carries a
percent-encoded principal — reaches the door spelled exactly as the listing showed it.

Example: `tai conversations transcript support-line bridge:support-line:+15550001111`

```console
$ tai conversations transcript [OPTIONS] {route_name} {thread_id}
```

| Argument | Description |
| --- | --- |
| `route_name` | Route name (slug). _(required)_ |
| `thread_id` | Thread id (e.g. bridge:support-line:+15550001111). _(required)_ |

| Option | Description |
| --- | --- |
| `--page` `&lt;int&gt;` | Page number, from 1. _(default: `1`)_ |
| `--page-size` `&lt;int&gt;` | Records per page (capped server-side). _(default: `50`)_ |
| `--order` `&lt;str&gt;` | Record order: 'asc' (oldest first) or 'desc'. _(default: `asc`)_ |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |
