Manage scheduled jobs.

```console
$ tai schedules [OPTIONS] COMMAND [ARGS]...
```

## `tai schedules add`

Create a schedule that runs a tool on a cadence, or once now with no cadence.

The cadence is one of `--every` / `--cron` / `--cadence` (at most one); with none
the tool runs once now. The four door-contract jqs (`--start-expr` / `--cancel-expr` /
`--resume-expr` / `--extras-expr`) make the schedule a parkable-driving door; any of
them requires `--execution-key`.

Example: `tai schedules add report --cron '0 9 * * *'`

```console
$ tai schedules add [OPTIONS] {tool_name}
```

| Argument | Description |
| --- | --- |
| `tool_name` | The tool to run on a schedule. _(required)_ |

| Option | Description |
| --- | --- |
| `--tool-kwargs` `&lt;str&gt;` | Tool arguments as a JSON object. |
| `--tool-kwargs-file` `&lt;str&gt;` | Read the tool arguments JSON object from a file, or from stdin when the path is '-', instead of putting a secret on the command line (a value on argv leaks via ps and shell history). Mutually exclusive with --tool-kwargs; --tool-kw pairs still override its keys. |
| `--tool-kw` `&lt;str&gt;` | A key=value tool argument (repeatable). |
| `--every` `SECONDS` | Run every SECONDS (an interval cadence, &gt; 0). |
| `--cron` `EXPR` | Run on a crontab EXPR (5 fields, or 6 with a leading seconds field). |
| `--cadence` `&lt;str&gt;` | The cadence as a JSON object, e.g. &#123;"kind": "interval", "every": 60&#125;. |
| `--schedule-name` `NAME` | The schedule's name (needs a cadence). |
| `--execution-key` `&lt;str&gt;` | The api key a contract-bearing recurring fire runs as (required with any contract jq); an account is refused. |
| `--start-expr` `&lt;str&gt;` | jq building the fired tool's kwargs over the tool arguments; null starts nothing. |
| `--cancel-expr` `&lt;str&gt;` | jq naming the parked interaction ids to cancel. |
| `--resume-expr` `&lt;str&gt;` | jq naming the parked interactions to resume or take. |
| `--extras-expr` `&lt;str&gt;` | jq building the extras mapping handed to the started target. |
| `--subject` `&lt;str&gt;` | The schedule-door state context as a JSON object the fire keys its writes on. |
| `--state-binding` `&lt;str&gt;` | The door-layer state binding as a JSON object. |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |

## `tai schedules delete`

Delete a schedule by name.

Example: `tai schedules delete report`

```console
$ tai schedules delete [OPTIONS] {name}
```

| Argument | Description |
| --- | --- |
| `name` | Schedule name. _(required)_ |

| Option | Description |
| --- | --- |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |

## `tai schedules list`

List the configured schedules (name, tool, cadence, enabled, next run).

Example: `tai schedules list`

```console
$ tai schedules list [OPTIONS]
```

| Option | Description |
| --- | --- |
| `--json` / `--no-json` | Emit raw JSON instead of human tables. |
