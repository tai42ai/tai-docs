Most of the platform runs with no services at all. A feature that needs Postgres,
Redis or another service says so on this page, names the setting that points at it,
and says what happens when it is missing.

A missing service shows up in one of four ways:

- **Boot refused.** The server does not start, and the error says why.
- **Off.** The feature reports itself off. Reads answer empty and writes answer `501`
  with a code that names the feature (see [What OFF looks like](/concepts/config-and-secrets#what-off-looks-like)).
- **In memory.** The feature works inside one process only, and boot logs a `WARNING`
  where the table says so.
- **Fails at first use.** Boot succeeds. The first call that needs the service raises
  an error that names the setting.

## How the settings resolve

- **Postgres.** A Postgres feature uses the [named database](/concepts/config-and-secrets#named-databases)
  its component binds to. A component binds to `default` unless `TAI_DB_BINDING_<COMPONENT>`
  says otherwise, so most features read `TAI_DATABASE_DEFAULT_PG_*`. A database counts as
  configured when its password is set. Set its host too: a password with no
  `TAI_DATABASE_<NAME>_PG_HOST` raises when the first connection is built.
- **Redis.** Each Redis feature has its own `<PREFIX>REDIS_URL`. When that is unset it
  uses the shared `TAI_DEFAULT_REDIS_URL`. Setting the shared URL turns on every Redis
  feature at once (see [Default connection namespace](/concepts/config-and-secrets#default-connection-namespace)).
- **Plain Redis or Redis with modules.** Almost every feature runs on any standard
  `redis-server` with no modules (`redis:7`, `redis:8` or Valkey). The `redis` checkpoint store and the
  `redis` LLM store, both the default, are the exceptions: they need the JSON and search
  modules. Redis 8 ships both, and the Compose bundle's Redis is Redis 8. A Redis 7 needs
  RedisJSON and RediSearch loaded. On a plain Redis the store's setup fails with
  `unknown command 'FT._LIST'`.

## The minimal deployment

A single `tai serve` worker with the `file` config mode and access control off needs
no Postgres and no Redis. Local tools and mounted MCP servers work. Each feature that
needs a service behaves as the tables below say.

```bash
export ACCESS_CONTROL_ENABLE=false
tai serve --transport http --host 127.0.0.1 --port 8000
```

Two defaults need a service unless you change them:

- **Access control is on by default.** With it on, the server needs an identity
  provider plugin, Postgres and Redis. See the core table.
- **The checkpoint store defaults to `redis`.** Any run that keeps memory
  needs a checkpoint store. Set `LLM_PROVIDER_CHECKPOINT=memory` for local work, or give it a
  Redis with modules or a Postgres. See the core table.

## Core

| Feature | What it needs | Setting | Without it |
| --- | --- | --- | --- |
| Tools, MCP mounts, manifest | Nothing | — | — |
| Worker bus | Plain Redis | `TAI_BUS_REDIS_URL` | One worker in `file` mode runs on a local no-op bus. Boot is refused for more than one `tai serve` worker, a config mode other than `file`, or a registered execution backend. See [Worker bus](/concepts/worker-bus). |
| Access control (on by default) | An identity provider plugin, Postgres (the `skeleton` database), and plain Redis for the gate's live context | `ACCESS_CONTROL_ENABLE`, `TAI_DATABASE_<NAME>_PG_*`, `ACCESS_CONTROL_REDIS_URL` | No identity provider: boot is refused. No Postgres or no gate Redis: the server boots, and every request that carries a key is denied with `Access Denied`, with the error logged. Set `ACCESS_CONTROL_ENABLE=false` to run without auth. |
| Schema check | Postgres (the `skeleton` database) | `TAI_DATABASE_<NAME>_PG_*` | The check is skipped. With a database set and a migration pending, boot is refused with `Run 'tai db migrate'`. |
| Background tool runs | Plain Redis | `TAI_TOOL_RUNS_REDIS_URL` | Off. |
| Interactions and notifications | Plain Redis | `INTERACTIONS_REDIS_URL` | Off. |
| Rate limiting on public doors | Plain Redis | `TAI_RATE_LIMIT_REDIS_URL` | Public doors are not throttled. Boot logs one `WARNING`. |
| Hooks | Plain Redis | `HOOKS_REDIS_URL` | In memory, with a `WARNING`. In-memory hooks and their kept runs are dropped on every config reload and on restart. Each `tai serve` worker refuses to boot without it when there is more than one worker, and boot is refused for a registered execution backend at any worker count. |
| Conversations | Plain Redis | `CONVERSATIONS_REDIS_URL` | In memory, with a `WARNING`. Every routing operation answers `501`. |
| Sub-MCP registrations | Plain Redis | `SUB_MCP_REDIS_URL` | In memory. Each `tai serve` worker refuses to boot without it when there is more than one worker. |
| Marketplace store, tool metadata, versioning and settings profiles | Postgres (the `skeleton` database) | `TAI_DATABASE_<NAME>_PG_*` | Off. See [OFF behavior per feature](/concepts/config-and-secrets#off-behavior-per-feature). |
| Subject state records | Postgres (the `states` database, bound to `default` unless `TAI_DB_BINDING_STATES` names another) | `TAI_DB_BINDING_STATES`, `TAI_DATABASE_<NAME>_PG_*` | Off. With its database set and a migration pending, boot is refused with `Run 'tai db migrate'`. |
| Run index | Postgres (the `skeleton` database) | `TAI_DATABASE_<NAME>_PG_*` | Runs are not indexed. |
| Connectors | Postgres (the `skeleton` database), plain Redis, and the `CONNECTORS_*` keys | `TAI_DATABASE_<NAME>_PG_*`, `CONNECTOR_STORE_REDIS_URL` | No Postgres: off. No Redis: the token cache reads Postgres, with a `WARNING`, and starting an OAuth connection fails at first use. |
| Checkpoint store for runs | `redis` (default): Redis with the JSON and search modules (Redis 8). `postgres`: Postgres. `memory` or `sqlite`: nothing (development only). | `LLM_PROVIDER_CHECKPOINT`, `LLM_PROVIDER_CHECKPOINT_CONN_STRING` | Fails at first use. With no conn string, `redis` reads `REDIS_URL` or `TAI_DEFAULT_REDIS_URL`, and `postgres` reads the base `PG_*` settings. See [Checkpoints](/operate/checkpoints). |
| LLM store (retrieval and deep agents) | `redis` (default): Redis with the JSON and search modules (Redis 8). `postgres`: Postgres. `memory` or `sqlite`: nothing. | `LLM_PROVIDER_STORE`, `LLM_PROVIDER_STORE_CONN_STRING` | Fails at first use. |
| Schedules | An execution backend plugin that exposes scheduling | — | Answers `501`. |
| Storage | A storage provider plugin | `storage_module` in the manifest | Answers `501`. |
| Inbound media | A storage provider plugin for the bytes, and the conversations store for each file's record | `storage_module` in the manifest, `CONVERSATIONS_REDIS_URL`, `MEDIA_INGEST_*` | No storage provider: every inbound file is rejected, the sender reads `That attachment could not be received.`, and a web chat upload answers `503` with `media_store_unavailable`. See [Inbound media](/operate/storage#inbound-media). |

`tai doctor` checks the `skeleton` database (with the migrator identity), its schema,
and the connector-store Redis (`CONNECTOR_STORE_REDIS_URL` or `TAI_DEFAULT_REDIS_URL`).
It counts an unconfigured one as a failure and exits non-zero. It does not check the
other Redis features.

## Babelfish Flows engine

| Feature | What it needs | Setting | Without it |
| --- | --- | --- | --- |
| Flow checkpoints (on by default) | The core checkpoint store | `FLOW_CHECKPOINT_ENABLED`, `LLM_PROVIDER_CHECKPOINT` | With the `redis` store and no Redis URL, boot is refused. A plain Redis fails at the first run. |
| Async park | A durable checkpoint store (`redis` or `postgres`) and the engine Redis | `LLM_PROVIDER_CHECKPOINT`, `FLOW_REDIS_URL` | No durable store: the park is refused. No engine Redis: the park fails when it writes its index. |
| Run status and abort across workers | Plain Redis | `FLOW_REDIS_URL` | Status and abort see only the runs in the same process. |
| Saved flows and the node palette | The platform Postgres (the `versioning` and `tool_meta` features) | `TAI_DATABASE_<NAME>_PG_PASSWORD` of the database the core `skeleton` component binds to (`TAI_DATABASE_DEFAULT_PG_PASSWORD` unless bound) | Boot is refused: the plugin [requires](/concepts/marketplace#required-platform-features) both features, so a deployment that loads it without the platform Postgres does not start, and a reload that would load it is refused. |
| Flow states | Postgres | `TAI_DB_BINDING_FLOWS_STATES` | Off unless the binding is set: the routes answer `503` with `states_unavailable`. With the binding set, an unconfigured database or a pending migration refuses boot. |

## Development only

These shapes are fine on a laptop and wrong in production:

- `ACCESS_CONTROL_ENABLE=false`: no auth on any request.
- `LLM_PROVIDER_CHECKPOINT=memory` or `sqlite`: runs do not survive a restart and cannot park.
- `sandbox-local`: sandboxed code runs on the host with no isolation.
- One worker with in-memory hooks, conversations and sub-MCP registrations.
- `CHANNEL_WEB_SESSION_COOKIE_SECURE=false`: the web chat cookie over plain HTTP.
